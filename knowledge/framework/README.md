# 家居分析框架文件

用户查看入口：[家居分析框架](家居分析框架.md)。

此目录为本地设计契约。没有执行器、数据库迁移或发布入口，不被当前网页构建复制。

## 文件用途

- `framework.json`：模块目录、资料字段、依赖顺序、报告章节和规则调用约定。
- `rule-template.json`：单条新规则的空模板。未填写项使用 `null` 或空数组；不得作为启用规则导入。
- `report-template.json`：新报告空结构。没有示例家庭、示例判断或占位分数。
- `家居分析框架.md`：可直接阅读的产品结构。

`schemaVersion` 是本目录数据契约版本，不是应用版本。字段清单用于后续建表、校验和接口设计；尚不是运行时验证器。

## 数据约定

1. 住宅、楼层、房间、家具、成员、结果和方案都通过稳定 ID 关联。所有记录须在同一住宅及其所有者权限范围内。
2. `[]` 表示当前没有记录，`null` 表示未知或尚未确定。未处理状态与已经核对后确认为空必须通过确认状态区分。
3. 户型坐标沿用现有图片坐标：左上角为原点，x 向右、y 向下，分别归一化至 0–1000。每层保留图片宽高；计算角度、面积前恢复图片纵横比。北向角为图片上方起顺时针 0–360°（不含 360）。
4. 每层朝向、边界和对象识别均保留确认状态。位置未知不填 `[0, 0]`；北向未知不填 `0`。计算分宫方法、中心点取法与缺角参考轮廓必须明确选择。
5. 现有 `sectors.percent` 是各方向内的实际面积占整屋面积的比例，不能作为缺角比例。缺角比例的分母为选定方法定义的参考方位面积。
6. 历史知识库的八方对应是参考映射，实际家庭成员角色单独确认。共用卧室允许多位成员；家庭象征、命卦择房、床头朝向分别配置。
7. 仅使用 `review_status='approved' AND enabled=1` 的历史规则。新规则还须具有完整条件、明确方法、来源、版本、审核人和时间。模板默认关闭。
8. 缺少资料、未选取法、无可用规则、运行失败时保留独立状态，不生成肯定或否定结论。按模块允许部分报告；整体“已完成”须覆盖全部选定模块。
9. 结果保存规则内容及来源快照、方法版本、输入版本和图上证据。旧报告不随规则库编辑而静默改变。输入修正后，依赖结果须重新分析。
10. 建议方案是独立版本，不覆盖原户型；房间分配和家具调整必须同时满足入住、尺寸、通行及不可移动对象等约束。冲突进入 `needs_review`，不自动强行分配。

## 待补规则

现有八方对应可读取；现有缺角判定和解读尚未启用。人物事项已补充12条候选；其余模块仅有结构。

优先补齐缺角的分宫、中心、边界、参考形状及阈值；随后补齐家庭角色匹配、共住优先级、分房及床位规则。其他模块按阶段增加。

`plannedRecords` 是未来逻辑记录设计，不是数据库已存在的表。人物事项知识表独立存放候选内容，见上级目录；本目录没有运行时调用或数据库适配器。

## 人物事项扩展（1.1）

新增 `person_goals` 模块与 `memberGoals` 逻辑记录设计。共有12个模块、19种逻辑记录。知识来源统一保存于上级知识库，取用前核对身份、目标、关系阶段、职业、时间与共住条件。新内容保持待审核、关闭；个案不自动推广为所有人的规则。
